# Agent-readable run records

> Pre-release record schema. The released Duke upload is one `circuit_id,value` CSV per problem; use [the problem folders](../../problems/README.md) for target IDs and final selected values. These CSV records remain useful as a job log but their `circuit,qubit,estimate` selection file is not an upload file.

These CSVs are the machine-readable path for the OTOC workflow. Keep the original challenge kit in `kit/` unchanged. Use the kit's template to create target and selected-prediction files:

```powershell
python scripts/run_csv.py init --dataset hidden --template "PATH_TO_HIDDEN_TEMPLATE.csv"
python scripts/run_csv.py init --dataset sample --template "PATH_TO_SAMPLE_TEMPLATE.csv"
```

`init` creates `targets_hidden.csv` and `targets_sample.csv` in official row order, plus `selected_hidden.csv` and `selected_sample.csv` with blank estimates. It also creates `jobs.csv` and `estimates.csv` with their headers. It refuses to replace a changed file. The `.example.csv` files document the tracked schemas; live CSVs are gitignored because they can contain private challenge data. IDs are always strings, so leading zeros survive. Every estimate must name an official `(circuit, qubit)` key.

| File | One row means | Editing rule |
| --- | --- | --- |
| `targets_*.csv` | One target in the official template | Generated by `init`; do not hand-invent IDs. |
| `jobs.csv` | One BlueQubit job attempt, including the affected qubit list and actual cost | Use `run_csv.py job`; a repeated action uses `attempt: 2` after checking the platform for an existing job. |
| `estimates.csv` | One raw numeric result for a qubit from a succeeded job | Use `run_csv.py estimate`; raw results are immutable. |
| `selected_*.csv` | One chosen prediction per official target | Use `run_csv.py select` after deciding on a direct or sample-validated estimator. |

To record a job, create a JSON object such as `scratch/job.json` and run `python scripts/run_csv.py job --json-file scratch/job.json`. Example content (illustrative IDs, not challenge data):

```json
{
  "dataset": "hidden",
  "circuit": "example-circuit",
  "method": "mps",
  "device": "mps.cpu",
  "kit_version": "release-id",
  "attempt": 1,
  "options": {"mps_bond_dimension": 64},
  "qubits": ["0", "1"],
  "status": "planned"
}
```

The command prints a stable `run_key`. Update the same action with `status`, `job_id`, time, and cost after querying the platform. Use a new attempt only for an intentional new job; a timeout alone does not prove the first submission failed. To record a returned value, use a second JSON file:

```json
{"run_key": "PASTE_PRINTED_RUN_KEY", "qubit": "0", "estimate": 0.42}
```

Run `python scripts/run_csv.py estimate --json-file scratch/estimate.json` only after the job status is `succeeded`. Run `python scripts/run_csv.py validate` to check the joins and numeric values. The helpers replace each small CSV atomically and take a shared file lock so multiple local agents cannot overwrite each other's updates. Never include API tokens or raw private challenge dumps in these records.

To choose a value for export, write `{"dataset":"hidden","circuit":"example-circuit","qubit":"0","estimate":0.42}` to a JSON file and run `python scripts/run_csv.py select --json-file PATH_TO_JSON`. The command changes only that target's `estimate` field and preserves official row order. Keep the model choice and sample-validation rationale in your run notes; the selected CSV intentionally contains only submission columns.

The selected CSV has the same `circuit,qubit,estimate` header as the official submission. Once every hidden row has a finite estimate:

```powershell
python scripts/checkpoint_submission.py --template "PATH_TO_HIDDEN_TEMPLATE.csv" --estimates runs/csv/selected_hidden.csv --check-only
python scripts/checkpoint_submission.py --template "PATH_TO_HIDDEN_TEMPLATE.csv" --estimates runs/csv/selected_hidden.csv --kind baseline
```

The protected baseline is saved at `data/checkpoints/baseline.csv`; further valid candidates can use `--kind latest`. The `.xlsx` workbooks and their `export_submission.py` path remain a separate manual fallback.
